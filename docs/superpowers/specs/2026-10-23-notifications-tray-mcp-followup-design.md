# Апгрейды Аи: уведомления, трей, MCP-редактор, свободные руки

Дата: 2026-10-23
Статус: утверждён 2026-10-23

## Зачем

Сделать Аю незаметнее в фоне и удобнее в повседневном использовании:

1. **Уведомления и трей** — напоминания и отчёты фоновых задач должны быть видны, даже когда окно Аи скрыто; быстрые переключатели — под рукой в трее.
2. **MCP-редактор** — добавлять и править MCP-серверы из консоли, а не вручную в `~/.aya/mcp.json`.
3. **Свободные руки** — после голосового ответа Ая ещё несколько секунд слушает, чтобы можно было продолжить разговор без Ctrl+Space. Функция включается/выключается, длительность редактируется.

## Что уже есть (на этом строим)

- Трей: «Показать Аю», «Открыть консоль», «Выход». Глобальный хоткей Alt+Shift+A.
- Инициативы: главное окно раз в 45 с опрашивает `/api/initiative`; Ая говорит. Есть `focus_mode` («тишина»), но принудительные напоминания (`initiative_force`) проходят и при нём.
- Голос: режимы `button` / `auto` / `hotkey`. В `auto` микрофон уже слушает постоянно, VAD сам останавливает запись после ~1,4 с тишины. Barge-in во время речи работает.
- MCP: только stdio. Конфиг `~/.aya/mcp.json`, формат `servers -> {name: {command, args, env, cwd, enabled}}`. `GET /api/mcp` сливает конфиг и статус; toggle включает/выключает один сервер.
- Python-ядро и SQLite; настройки через `db.setting`.
- Уведомлений Tauri сейчас нет; плагин `tauri-plugin-notification` 2.7 доступен.

## Границы

- Никакого wake-word («Ая, ...») — только окно дослушивания после ответа.
- MCP только stdio; HTTP/SSE-транспорты не добавляем.
- Уведомления только пока приложение запущено; облачного push нет.
- Обычные ответы в чате не дублируются тостами.
- Автообновление, установщик и автозапуск не трогаем.

## 1. Уведомления и трей

### Поведение

**Тост показывается, когда:**
- окно Аи скрыто (Alt+Shift+A) **или свёрнуто**, **или**
- включена «Тишина» (`focus_mode`).

«Скрыто» = `!isVisible()` или `isMinimized()`. Открытая консоль не считается «Ая видна» — это отдельное окно.

**События для тоста:** любая инициатива из `/api/initiative` — напоминания, отчёты фоновых задач, входящие Telegram, утренний/вечерний дайджест. Заголовок «Ая», текст — ответ Аи, обрезанный до 240 символов.

**Что делает «Тишина»:**
- глушит проактивные инициативы, включая legacy-фолбэки `welcome_back` / `light_ping` (сейчас они обходят `focus_mode` — чиним в `state.initiative_check`);
- принудительные напоминания продолжают приходить и озвучиваться (как обещает консоль: «напоминания работают всегда»);
- не выключает озвучку ответов на сообщения пользователя и голосовых ходов «свободных рук»;
- не останавливает уже играющую речь (v1).

**Ограничения v1:**
- клик по тосту не открывает Аю (надёжного click-события на Windows не обещаем); для показа есть трей и Alt+Shift+A;
- тост — визуальная страховка, речь не заменяет и не отменяет.

### Трей

Меню:

```
Показать Аю
Открыть консоль
──────────────
Свободные руки   [✓]
Тишина           [✓]
──────────────
Выход
```

- «Показать Аю» — показать, развернуть, если свёрнуто, и сфокусировать.
- «Открыть консоль» — показать, развернуть и сфокусировать окно консоли.
- «Свободные руки» — переключает `voice_followup`; состояние синхронизировано с консолью.
- «Тишина» — переключает `focus_mode`; состояние синхронизировано с консолью.
- Чекбоксы обновляются из фронтенда командой Rust `set_tray_check(id, checked)`; клик по пункту шлёт событие в главное окно, фронтенд сохраняет настройку и подтверждает состояние.
- Начальная синхронизация — после загрузки главного окна (читаем `/api/config` и `/api/proactive`).
- Пункта «микрофон» нет: для ручного ввода остаётся Ctrl+Space/кнопка.

### Реализация

- Rust: `tauri-plugin-notification`, `CheckMenuItem` для двух переключателей, события `tray-toggle-followup` / `tray-toggle-focus`, команда `set_tray_check`. Capability: `notification:default`, `core:window:allow-is-visible`, `core:window:allow-is-minimized`, `core:window:allow-unminimize`.
- Python: в `behavior/state.py` `initiative_check()` после блока `initiative_force` возвращает `""`, если `focus_mode=1` или `proactive_enabled=0`; тесты на legacy-фолбэки.
- JS: `src/notify.ts` — обёртка плагина (проверка/запрос разрешения, `sendNotification`); `src/notify-decision.ts` — чистые функции `shouldToast(visible, focus)` и `toastBody(text)` с тестами.
- `main.ts`:
  - в `pollInitiative` после получения инициативы: `isVisible()` + актуальный `focus` из `/api/proactive` → при необходимости тост;
  - слушатели tray-событий;
  - синхронизация чекбоксов при старте и при изменении настроек (poll `/api/config` уже есть; `/api/proactive` — раз в 5–10 с).
- Для видимости окна — `getCurrentWindow().isVisible()` из `@tauri-apps/api/window`.

### Критерии готовности

- Окно скрыто или свёрнуто → напоминание даёт тост; окно видно и «Тишина» выключена → тоста нет, Ая говорит.
- «Тишина» включена → тост есть, проактивные и legacy-инициативы не генерируются; принудительные напоминания проходят.
- Оба чекбокса в трее переключают настройки и совпадают с консолью после перезапуска; «Показать Аю» разворачивает свёрнутое окно.
- Разрешение на уведомления запрашивается один раз; при отказе приложение работает без тостов.

## 2. MCP-редактор

### Поведение

В консоли, карточка «MCP-серверы»:

- список серверов (как сейчас): имя, статус, инструменты, переключатели enabled/permitted;
- кнопка «Добавить сервер» → форма:
  - имя (латиница, цифры, дефис; 1–48 символов),
  - команда (например `npx`, `python`, `cmd`),
  - аргументы — по одному в строке,
  - env — строки `KEY=VALUE`,
  - рабочая папка (необязательно),
  - «включён»;
- у каждого сервера: «изменить» (та же форма), «проверить», «удалить»;
- «проверить» запускает сервер временно, делает handshake и `tools/list`, показывает инструменты или ошибку, затем останавливает;
- ошибки старта показываются в карточке; конфиг сохраняется даже если сервер не поднялся;
- подсказка: конфиг лежит в `~/.aya/mcp.json`, сервер запускает команду на твоём ПК, секреты хранятся локально в открытом виде.

### API

- `GET /api/mcp` — расширить: к `command`, `args`, `enabled`, `permitted`, `connected`, `error`, `tools` добавить `env`, `cwd`.
- `POST /api/mcp/save` — `{name, old_name?, command, args, env, cwd, enabled}`.
  - валидация имени/команды/типов;
  - при переименовании — остановить старый сервер, перенести permission-ключ;
  - атомарная запись `mcp.json` (tmp + `os.replace`), остальные ключи конфига сохраняются;
  - если `enabled` — запустить и вернуть ошибку старта, не откатывая конфиг; если выключен — остановить.
- `POST /api/mcp/delete` — `{name}`: остановить, удалить из конфига и permission, вернуть `{ok}`.
- `POST /api/mcp/test` — спек сервера: временный `McpServer`, `start` + `initialize` + `load_tools`, `stop`; вернуть `{ok, tools, error}`.
- Существующие `/api/mcp/toggle` и `/api/mcp/perm/{server}` не меняем.

### Реализация

- `core/mcp.py`: чистые помощники `validate_spec`, `save_server`, `delete_server`, `test_server`, `write_config` (атомарно). Без новых зависимостей.
- `core/main.py`: Pydantic-модели и эндпоинты, тонкие обёртки над помощниками.
- `src/mcp-editor.ts`: чистые функции `parseArgs`, `parseEnv`, `formatArgs`, `formatEnv`, `validateServerName` + vitest.
- `console.ts`: переписать `mcpCard` на форму; сохранение/тест/удаление через API.

### Критерии готовности

- Можно создать сервер с нуля, отредактировать, переименовать, выключить, включить, удалить.
- «Проверить» показывает список инструментов или текст ошибки.
- `mcp.json` остаётся валидным; существующий `playwright` не теряется.
- Невалидное имя/пустая команда отклоняются с понятным текстом.
- Юнит-тесты помощников и API (с мок-сервером из `test_mcp.py`).

## 3. Свободные руки

### Настройки

- `voice_followup` — `0`/`1`, по умолчанию **выключено**.
- `voice_followup_sec` — секунды ожидания, по умолчанию **6**, допустимо **2–30**.
- Отдаются/принимаются в `GET/POST /api/config` как `followup: bool` и `followup_sec: int`.
- Консоль, карточка «Озвучка и голос»: переключатель «свободные руки» и поле «слушать после ответа, сек» (2–30).
- Трей: чекбокс «Свободные руки» (без длительности).

### Поведение

- Работает только когда:
  - функция включена;
  - режим голоса **не** `auto` (там микрофон и так слушает постоянно — показываем подсказку);
  - главное окно Аи видно, не свёрнуто, и открыта панель чата (в ней индикатор микрофона); закрытие панели/сворачивание отменяет окно;
  - нет `busy`, записи или ручного удержания микрофона.
- Взводится **после голосового хода**: пользователь сказал голосом (или ответил в окне дослушивания), Ая ответила и договорила. После текстовых сообщений микрофон сам не открывается.
- Окно дослушивания N секунд: ждём начало речи. Индикатор у микрофона + подсказка «слушаю…».
- Начало речи (2 тика VAD) → обычная запись; конец — по тишине ~1,4 с, максимум 30 с.
- Тишина все N секунд → выключаемся молча.
- После валидной расшифровки и озвученного ответа — снова окно дослушивания (цикл).
- Пустая расшифровка или ошибка STT → цикл останавливается, окно заново не взводится (иначе шум/сбой держат микрофон открытым).
- Не взводится, если ответ пустой, без озвучки (`spokeAny === false`), был прерван (`speakAbort`) или остался `pending`-экшен: голосовое «да» не должно уходить в новый чат вместо подтверждения.
- Инициатива, пришедшая во время ожидания, отменяет окно; во время записи инициативы и так не запускаются (`pollInitiative` проверяет запись).
- Отменяется при: ручном Ctrl+Space/кнопке, отправке текста, «Стоп», скрытии/сворачивании окна, закрытии панели чата, выключении настройки.
- В `auto`-режиме настройка неактивна (в консоли — подсказка).

### Реализация

- `src/followup.ts` — небольшой предсказуемый автомат/таймер с инъекцией времени:
  - `arm(seconds)`, `remaining(now)`, `expire(now)`, `cancel()`, `active(now)`;
  - тесты vitest на взведение, остаток, истечение, отмену.
- `main.ts`:
  - флаг «ход был голосовым» ставится в `onRecStop`, сбрасывается после `sendToAya`;
  - после завершения очереди TTS (pump) и при `!speakAbort` — `followup.arm(sec)`;
  - отдельный интервал VAD на время окна; переиспользуем пороги `VOICE_VAD`, `quietCount`;
  - индикатор и таймер на кнопке микрофона;
  - отмена по событиям выше.
- `voice-ctl.ts`/`/api/config` — проброс настроек; тест Python на clamp 2–30 и roundtrip.
- Трей-чекбокс синхронизируется с `voice_followup`.

### Критерии готовности

- Включено, 6 с: после голосового вопроса и ответа Ая слушает 6 с; сказал «а почему?» — записала и ответила без Ctrl+Space.
- Молчание 6 с — микрофон закрылся, ничего не отправилось.
- Выключено — после ответа микрофон не открывается.
- В `auto` — поведение не меняется, настройка неактивна.
- Скрытие/сворачивание окна, закрытие панели чата, «Стоп», ручной микрофон отменяют ожидание.
- Пустая расшифровка/ошибка STT останавливают цикл; при `pending`-экшене окно не взводится.
- Длительность 2–30; значения вне диапазона зажимаются.

## Общие требования

- Всё локально, без новых сетевых сервисов.
- Новые зависимости: только `tauri-plugin-notification` (Rust + JS) и `@tauri-apps/api/window` (уже в `@tauri-apps/api`).
- TDD: Python и чистые TS-функции — тесты сначала; интеграция UI/трея/микрофона проверяется вручную (юнит-тестами не покрывается).
- Не ломать: хоткей Alt+Shift+A, Ctrl+Space, barge-in, существующие MCP-серверы, `auto`-режим.
- После изменений: `pytest`, `npm test`, `tsc`, `cargo test`, затем пересборка релиза.

## Порядок работ

1. Python: настройки follow-up + MCP CRUD/test (тесты-first).
2. Чистые TS-помощники: notify-decision, mcp-editor, followup (тесты-first).
3. Консоль: карточки MCP и голоса.

6. Полная проверка + ручной прогон + релизная сборка.

## Решения, которые я принял сам (проверь)

- Тост только при скрытом/свёрнутом окне или включённой «Тишине»; иначе говорит голосом.
- «Тишина» глушит проактивные и legacy-инициативы, но не озвучку ответов и не принудительные напоминания; уже играющую речь не останавливает.
- Клик по тосту в v1 ничего не открывает.
- Трей: ровно два чекбокса — «Свободные руки» и «Тишина»; пункта «микрофон» нет. «Показать Аю»/«Открыть консоль» разворачивают свёрнутые окна.
- Свободные руки взводятся только после голосового хода, не после текста.
- Свободные руки не работают при скрытом/свёрнутом окне, закрытой панели чата и в режиме `auto`.
- Пустая расшифровка/ошибка STT/пустой ответ без озвучки/`pending`-экшен останавливают цикл; инициатива во время ожидания отменяет окно.
- Длительность по умолчанию 6 с, диапазон 2–30.
- MCP только stdio; аргументы по одному в строке, env `KEY=VALUE`; секреты в открытом виде локально.
- «Проверить» поднимает временный процесс, не меняя включённость сервера.
